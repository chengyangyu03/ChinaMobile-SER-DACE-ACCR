# 完整私有测试集推理效率

## 测量对象

效率实验使用完整的 2025 年 7 月私有测试集，共 3,025 条。原始音频合计
40,056.08 秒（11.1267 小时）；按发布配置将每条音频截断到 16 秒后，实际送入
模型的音频合计 37,204.38 秒（10.3346 小时），其中 670 条发生截断。

测试机器配有 NVIDIA GeForce RTX 3090 24 GB，驱动 575.64；单卡实验使用一张
卡，三卡实验使用空闲的 GPU 0/3/6。CPU 为两颗 Intel Xeon Platinum 8175M，
共 48 个物理核心。软件环境为 Python 3.10、
PyTorch 2.6.0+cu124、Transformers 5.12.1、PEFT 0.19.1 和
bitsandbytes 0.46.1。

每次启动前都要求目标 GPU 基线占用不超过 500 MiB。单卡四次实测基线均为
15 MiB；三卡 DACE/ACCR 的 GPU 0/3/6 基线分别为 36/15/15 MiB，实验期间
没有其他进程使用目标 GPU。服务器 CPU 为多人共享资源，没有
为本实验做独占绑核，因此墙钟时间应视为这台共享服务器上的单次观测值，而不是
所有 RTX 3090 机器都必须达到的固定数值。

## 显存与并行配置

- **低显存**：batch size 1，最大音频 16 秒。用于测量单卡部署的最低实测需求。
- **高吞吐**：batch size 56，最大音频 16 秒。batch size 先在测试集中最长的
  64 条音频上，从 32、40、48、56 逐级试跑，选择可稳定运行且接近占满
  24 GB 显存的最大档。
- **三卡高吞吐**：GPU 0/3/6 各自使用 batch size 56 和 16 秒上限。程序按
  截断后音频时长做完整对话级 LPT 分片，三片为 1006/1011/1008 条，
  有效音频为 12403.13/12403.13/12398.12 秒；每个对话只落到一张卡。
  三个 worker 各使用 16 个 CPU 线程，避免并发加载时 CPU 线程过量竞争。

所有配置使用相同模型权重、冻结参数和数值精度；DACE 与 ACCR 不并发运行。
多卡合并后恢复原始输入顺序，并断言 3,025 个 `wav_name` 无缺失、无重复。
公开表格中的显存峰值来自每 0.5 秒读取一次
`nvidia-smi` 的整卡占用，它比程序 summary 中 PyTorch
`max_memory_allocated` 更适合做容量规划。

`总时间` 从启动全新 Python 子进程开始，到进程退出为止，包含 Python
导入、输入与冻结参数校验、处理器/基座/primary 加载、全部模型前向、adapter
切换、冻结校准、无模型对话平滑以及 CSV/JSON 写盘。它不是只统计模型
forward 的“纯推理时间”。基座已位于本地磁盘；由于测试机器为共享服务器，
没有强制清空操作系统页缓存。

三卡 `总时间` 从启动 `run_multigpu.sh` 开始，到合并 summary 写完为止，还包含
约 2.4 秒的完整对话分片。每卡启动一个独立 Python 进程并各加载一份 4-bit
基座；因此三卡节省墙钟而不节省总算力、显存总量或系统内存。三卡 DACE 和
ACCR 相对对应单卡 batch 56 分别为 2.75× 和 2.77× 加速。三卡模式没有记录
可与 GNU `time -v` 单进程 RSS 直接等价的聚合 RSS，表中不据此给出系统内存
实测值。

显存有两个不同口径：

- `nvidia-smi` 整进程峰值包含 CUDA 上下文、PyTorch 缓存分配器和非 PyTorch
  CUDA 内存，是本仓库给出硬件建议的依据。
- PyTorch 已分配峰值只统计活跃 tensor。此前观察到的约 6.42 GiB 属于这个
  较窄口径，不能据此断言 7 GB 显存足够运行完整程序。

## 如何解释结果

低显存与单卡高吞吐的差异仅是 GPU batch size；三卡模式再增加完整对话级任务
并行，因此应结合显存、系统内存、GPU 数量和总耗时要求选择。ACCR 的第二
adapter 调用率依赖新数据的置信度分布；新测试集的平均
前向数和耗时不保证与私有测试集完全相同。DACE 始终执行两次前向，成本更稳定。

ACCR 的冻结阈值作用于浮点概率，batch size 改变可能使极少数阈值边界样本改变
路由或最终类别。项目默认 batch size 2 的结果仍是 2,422 条正确、1,196 条调用
secondary、平均 1.3954 次前向；本次 batch size 1 为 2,423 条正确/1,197 条
调用，batch size 56 为 2,422 条正确/1,198 条调用。两个效率档只按显存目标
选择，没有根据测试准确率重新选择或校准参数，所以模型卡首页继续用默认配置
作为统一精度/成本基准。三卡 batch 56 因分片后的 batch 组成不同，为 2,423
条正确/1,197 条调用；与单卡 batch 56 只有 1 条改变路由和最终预测。DACE 在
单卡和三卡的各实测配置下均保持 2,427 条正确。

这里报告的是单次冷启动完整任务。若服务进程常驻并复用已经加载的模型，单批
请求不会重复承担全部加载时间，但那属于不同的部署协议，不应直接与本页数字
混用。
